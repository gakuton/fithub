## 【重要原則】マージ前に必ず満たすこと

以下の条件が揃っていない場合は **マージ禁止**。「マージ後に設定する」は認めない。

1. **コードが必要とする env vars が Vercel に設定済みであること**
2. **DBマイグレーションが本番DBに適用済みであること**（コードより先、または同時）
3. **「マージ後に実施」という手順が PR に残っていないこと**

## チェック項目を順番に実行する

### 1. TypeScript型チェック
```bash
npx tsc --noEmit
```
エラーがあれば報告して修正を促す。エラーがなければ「✅ 型チェック OK」と伝える。

### 2. ビルド確認
```bash
npm run build
```
ビルドエラーがあれば報告して修正を促す。成功すれば「✅ ビルド OK」と伝える。

### 3. 環境変数チェック

`.env.local` に以下が含まれているか確認する（値は表示しない）：
- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
- `CLERK_SECRET_KEY`
- `ANTHROPIC_API_KEY`
- `TURSO_DATABASE_URL`
- `TURSO_AUTH_TOKEN`

上記を確認した後、必ずユーザーに以下を口頭確認する：

> **「Vercel の本番環境にも同じ変数が設定済みですか？設定前のマージは障害になります。」**

ユーザーが「設定済み」と答えるまでこのチェックを ✅ にしない。

### 4. 未コミットの変更チェック
git statusを確認し、コミットし忘れているファイルがあれば警告する。

### 5. マイグレーションチェック

`drizzle/migrations/` の最新ファイルと `lib/db/schema.ts` の変更日時を比較する。
スキーマを変更してマイグレーションを生成していない可能性がある場合は警告する。

```
!`ls -lt drizzle/migrations/ | head -5`
```

スキーマ変更が含まれる場合、ユーザーに確認する：

> **「本番DBへのマイグレーション適用はコードのデプロイより先か同時に行ってください。コードが先にデプロイされると新カラムを参照して500エラーになります。」**

### 6. 外部サービス依存チェック

今回の変更が以下を新たに追加・変更している場合は確認する：

- **新しい外部サービス**（Clerk, Stripe, SendGrid等）→ APIキー取得・Vercel設定が完了しているか
- **既存サービスのキー更新**（APIキーローテーション等）→ Vercelの値が更新済みか
- **サービスのWebhook/Callback URL設定**（Clerk の Allowed Origins 等）→ 本番URLが登録済みか

該当があればユーザーに確認を促す。該当なければスキップ。

### 7. PR内容の確認

PR の description や commit message に **「マージ後に実施」「マージ後に設定」** という記述がないか確認する。

```
!`git log main..HEAD --format="%B" | head -60`
```

該当があれば以下を伝える：

> **「PR に『マージ後に実施』という手順が残っています。その手順を先に完了させてからマージしてください。」**

## 最終サマリー

全チェック完了後、以下の形式でサマリーを出す：

| チェック項目 | 結果 |
|---|---|
| TypeScript | ✅ / ❌ |
| ビルド | ✅ / ❌ |
| Vercel 環境変数（確認済み） | ✅ / ❌ |
| 未コミット | ✅ / ⚠️ |
| マイグレーション適用順序 | ✅ / ⚠️ |
| 外部サービス依存 | ✅ / ⚠️ / — |
| 「マージ後に実施」記述なし | ✅ / ❌ |

❌ が1つでもある場合は「**マージ不可**」と明示する。⚠️ のみの場合はユーザー判断を仰ぐ。全て ✅ の場合のみ「デプロイ準備完了です」と伝える。
