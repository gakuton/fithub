argument-hint: [フェーズ番号] [機能名（例: 7 AIデータ入力）]
---

## 既存フェーズの確認

```
!`ls docs/`
```

```
!`cat CLAUDE.md`
```

## 引数の解釈

$ARGUMENTS からフェーズ番号と機能名を読み取る。
引数がない場合は「使い方: /new-phase [フェーズ番号] [機能名]（例: /new-phase 7 AIデータ入力）」と伝えて終了する。

## 作成するファイル

以下の2ファイルを `docs/Phase{フェーズ番号}/` ディレクトリに作成する。

---

### 1. 要求定義書.md

以下の構成でMarkdownを作成する：

```
# Phase{N} 要求定義書 — {機能名}

## 概要
（機能の目的と背景を1〜2段落で記述。ユーザー課題と解決アプローチ）

## ユースケース
### UC-01: （主要ユースケース名）
- **アクター**: Gakuto
- **事前条件**: 
- **基本フロー**: 
- **代替フロー**: 

### UC-02: （副ユースケース名）
（同様の構成）

## 機能要件
| # | 要件 | 優先度 |
|---|---|---|
| FR-01 | | Must |

## 非機能要件
- パフォーマンス: 
- セキュリティ: 
- モバイル対応: 

## スコープ外
- （今回の実装に含めないもの）

## 用語定義
| 用語 | 説明 |
|---|---|
```

---

### 2. 設計ドキュメント.md

以下の構成でMarkdownを作成する：

```
# Phase{N} 設計ドキュメント — {機能名}

## 1. DBスキーマ変更
（新規テーブル・カラム追加があれば記述。なければ「変更なし」）

## 2. 新規パッケージ
（npm installが必要なものがあれば記述。なければ「なし」）

## 3. Zodスキーマ
（バリデーションスキーマの設計）

## 4. APIエンドポイント
| メソッド | パス | 説明 |
|---|---|---|

## 5. UIコンポーネント
（新規コンポーネントの一覧と役割）

## 6. 実装計画（PR分割）
| PR | 内容 |
|---|---|
| PR-A | |
| PR-B | |
```

---

## 作成後の案内

- 作成したファイルのパスを伝える
- CLAUDE.md の「実装予定」セクションに追記するか確認する
- 「要求定義の詳細を一緒に詰めますか？」と聞く
