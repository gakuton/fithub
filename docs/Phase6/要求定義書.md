# 要求定義書 — AIパーソナルトレーナーチャット機能（Phase 6）

**作成日：** 2026-04-26　｜　**バージョン：** 1.0　｜　**フェーズ：** 要求定義

---

## プロダクト概要

トレーニング・食事・体組成のデータが蓄積されたFitHubに、**アプリ内専属AIパーソナルトレーナー**を追加する。

従来はテキスト出力→ChatGPTへコピペという外部依存フローを取っていたが、毎回コンテキストがリセットされる問題と、アプリ切り替えの手間が課題となっていた。本フェーズでは、FitHubのデータを常時参照するAIチャット機能をアプリ内に構築し、いつでも・どこからでも専属トレーナーに相談できる環境を実現する。

---

## 1. 背景と課題

### 課題①：毎回コンテキストがリセットされる

現在、AIへの相談はChatGPT等の外部ツールを利用しており、会話セッションをまたいで履歴が引き継がれない。ユーザーは1日4〜5回程度AIに質問するが、毎回「自分のデータ」を貼り付けるか、コンテキストなしで質問する必要がある。

### 課題②：アプリ切り替えの摩擦

FitHubでテキスト出力 → コピー → ChatGPTアプリを開いてペースト、という操作フローが毎回必要で煩雑。トレーニング後や食事入力直後など、アプリ内で完結してほしい場面が多い。

### 課題③：長期データを踏まえたアドバイスの精度

外部AIに都度コンテキストを貼り付ける方式では、直近1ヶ月の体重推移・トレーニングボリュームの変化など長期トレンドを含めた精度の高いアドバイスが得られにくい。

## 4. 拡張ユースケース

### UC-01：AIパーソナルトレーナーとチャット（基本会話）

| 項目 | 内容 |
|-----|------|
| **事前条件** | アプリにアクセスできる（データがゼロ件でも可） |
| **事後条件** | AIの回答がチャット画面に表示され、会話がlocalStorageに当日分として保存される |
| **開始条件** | ユーザーがAIに質問・相談したい（トレーニング後・食事入力後・就寝前・気が向いた時など1日4〜5回程度） |

#### シナリオの流れ（クイックアクション利用）

```
BottomNav「AI」タブをタップ
    ↓
チャット画面が表示される
（会話履歴がなければクイックアクションボタンが4つ並ぶ）
    ↓
クイックアクションボタンをタップ
（例：「今日のトレーニングを振り返る」）
    ↓
対応するメッセージが入力欄に自動入力される
    ↓
送信ボタンをタップ
    ↓
ローディング表示（AIが回答生成中）
    ↓
AIの回答がメッセージバブルにストリーミング表示される
    ↓
続けて会話できる状態になる
```

#### シナリオの流れ（自由入力）

```
BottomNav「AI」タブをタップ
    ↓
チャット画面が表示される
    ↓
テキスト入力欄に質問を入力
（例：「今週のプロテイン摂取量は目標に届いていますか？」）
    ↓
送信ボタンをタップ
    ↓
ローディング表示
    ↓
AIの回答がストリーミング表示される
    ↓
続けて会話できる状態になる
```

#### 構成要素

| 構成要素 | 詳細 |
|---------|------|
| アクター | トレーニーユーザー |
| プレース | どこでも（スマートフォン） |
| インターフェイス | AIチャット画面（`/chat`）。BottomNavの5番目タブから遷移 |
| ビジネスロジック | ①ユーザーメッセージを受信 ②メッセージ内の期間キーワードを解析し参照期間を決定（デフォルト：直近30日） ③食事コンテキストの詳細度を判定（デフォルト：日次集計のみ。「食事の詳細」「何を食べたか」等のキーワードがある場合は食品名まで含める） ④対象期間のデータをDBから取得 ⑤コンテキスト文字列を組み立て ⑥システムプロンプト＋コンテキスト＋直近5往復の会話履歴＋ユーザーメッセージ → Claude API（claude-sonnet-4-6）へ送信 ⑦レスポンスをストリーミングで返却しクライアントに表示 |
| データモデル | 新規DBテーブルなし。会話履歴はlocalStorageに保存（Section 8参照） |
| 特記事項 | Claude APIキーはサーバーサイド環境変数（`ANTHROPIC_API_KEY`）で管理し、クライアントには露出しない。既存の`lib/utils/export.ts`のコンテキスト生成ロジックを参考に、期間指定対応の新関数を作成する |

### UC-02：セッション継続（当日中の再開）

| 項目 | 内容 |
|-----|------|
| **事前条件** | 当日すでにAIとの会話が存在する（localStorageに保存済み） |
| **事後条件** | 前回の会話が復元された状態でチャットが続けられる |
| **開始条件** | 同日中にアプリを再起動・ブラウザタブを再度開く |

#### シナリオの流れ

```
BottomNav「AI」タブをタップ（同日中の再訪問）
    ↓
localStorageから当日のセッションを自動読み込み
    ↓
前回の会話履歴が表示された状態で画面が開く
（クイックアクションボタンは非表示。入力欄のみ表示）
    ↓
続きから会話できる状態になる
```

#### 構成要素

| 構成要素 | 詳細 |
|---------|------|
| アクター | トレーニーユーザー |
| プレース | どこでも（スマートフォン） |
| インターフェイス | AIチャット画面（`/chat`） |
| ビジネスロジック | ページロード時にlocalStorageのセッションを確認。現在時刻が午前3時以降なら当日日付、午前3時未満なら前日日付を「有効セッション日付」とみなし、一致すれば会話を復元。不一致の場合は古いキーを全削除し初期状態を表示 |
| データモデル | localStorage `fithub_chat_{YYYY-MM-DD}` → `ChatSession`型（Section 8参照） |
| 特記事項 | セッションは翌日午前3時以降の初回アクセス時に自動無効化。例：26日23時開始の会話は27日2時59分まで継続可能。手動クリアは今フェーズのスコープ外 |

## 5. コンテキスト自動参照仕様

### 5-1. 参照期間の決定ロジック

ユーザーメッセージ内の期間キーワードをサーバーサイドで解析し、DBから取得する期間を動的に決定する。キーワードが複数ある場合は最長期間を採用する。

| キーワード例 | 参照期間 |
|------------|---------|
| 「今日」「今日の」 | 当日のみ |
| 「今週」「この1週間」 | 直近7日 |
| 「先週」 | 先週（月〜日） |
| 「今月」「この1ヶ月」 | 直近30日（デフォルトと同じ） |
| 「先月」 | 先月1日〜末日 |
| 「3ヶ月」「3か月」 | 直近90日 |
| 「半年」「6ヶ月」「6か月」 | 直近180日 |
| 「1年」「今年」「12ヶ月」 | 直近365日 |
| キーワードなし（デフォルト） | 直近30日 |

### 5-2. 参照データ一覧

| データ種別 | 取得内容 | 参照テーブル | 期間適用 |
|-----------|---------|------------|---------|
| トレーニング履歴 | 日付・種目名・重量・reps・推定1RM | `workout_sets`, `exercises` | ✅ |
| 食事履歴 | **デフォルト：日次PFC集計のみ**（日付・合計P/F/C/kcal）。「食事の詳細」「何を食べたか」等のキーワードがある場合のみ食品名・食事タイプ単位の詳細を含める | `meals`, `meal_items` | ✅ |
| 体組成履歴 | 日付・体重・体脂肪率・骨格筋量・BMR | `body_compositions` | ✅ |
| プロフィール | 性別・身長・生年月日・活動レベル | `demographic_data` | ❌（全件） |
| 目標 | カテゴリ・説明・達成状態 | `motivations` | ❌（全件） |

## 7. AIシステムプロンプト設計

```
あなたはFitHubユーザー専属のパーソナルトレーナーです。
以下のルールに従って回答してください。

【役割と行動指針】
- ユーザーのトレーニング・食事・体組成データを基に、具体的かつ実践的なアドバイスを提供する
- 発言には科学的根拠を伴わせる（必要に応じて研究・理論・計算根拠を示す）
- ですます調を使い、プロフェッショナルなトーンを維持する
- 過度な感情表現（「素晴らしい！」「最高です！」等）は控える
- データが不足している場合は、その旨を明示した上で回答する
- 回答は簡潔かつ実践的にまとめる

以下はユーザーの現在のフィットネスデータです：
{context}
```

## 8. データモデル（localStorageスキーマ）

新規DBテーブルは不要。会話履歴はブラウザのlocalStorageに保存する。

```typescript
// localStorageキー命名規則
const SESSION_KEY = `fithub_chat_${format(new Date(), 'yyyy-MM-dd')}`
// 例: "fithub_chat_2026-04-26"

// メッセージ型
type ChatMessage = {
  role: 'user' | 'assistant'
  content: string
  createdAt: string  // ISO 8601形式
}

// セッション型（localStorageに保存する値）
type ChatSession = {
  date: string        // YYYY-MM-DD（有効期限判定に使用）
  messages: ChatMessage[]
}
```

**セッション管理ルール：**

| タイミング | 処理 |
|-----------|------|
| ページロード時 | 現在時刻が午前3時以降 → 当日日付、午前3時未満 → 前日日付を有効セッション日付とし、一致するキーがあれば会話を復元 |
| ページロード時（不一致） | 保存済みセッションが有効セッション日付と異なる → 古いキーを全削除し、初期状態を表示 |
| メッセージ送受信ごと | localStorageを上書き保存 |
| 翌日午前3時以降の初回アクセス | 自動的に空の状態で開始（前日セッションを削除） |
| Claude APIへの送信 | localStorageに保存されている全メッセージのうち**直近5往復（10メッセージ）のみ**をAPIに渡す。画面上は全履歴を表示したままにする |

## 10. 非機能要件

| 項目 | 要件 |
|-----|------|
| UI/UX | モバイルファースト。入力欄は常に画面下部に固定。ソフトキーボード表示時も入力欄が見切れない実装（`dvh`単位を使用） |
| 使用AIモデル | `claude-sonnet-4-6`（Anthropic Claude Sonnet）固定 |
| レスポンス表示 | ストリーミング表示でAIの回答をリアルタイムに描画（体感待ち時間の短縮） |
| APIセキュリティ | `ANTHROPIC_API_KEY`はサーバーサイド環境変数で管理。クライアントバンドルには含めない |
| コスト管理 | 個人利用のためPhase 6では使用量制限なし。Phase 5（マルチユーザー）導入時にユーザー単位の制限を検討 |
| エラーハンドリング | API呼び出し失敗時はユーザーフレンドリーなメッセージを表示し、再試行を可能にする |
| 対応環境 | 既存と同じ（スマートフォンブラウザ：Safari / Chrome） |
| 最小タップ領域 | 既存方針に準拠（44px以上） |

## 11. スコープ外

| 機能 | 理由 |
|-----|------|
| 会話履歴のDB保存（永続化） | localStorageで1日保持要件を満たす。DB保存はPhase 5の認証対応後に再検討 |
| 手動クリアボタン（「会話をリセット」） | 1日保持要件の範囲では不要。ニーズが出た場合は後続フェーズで追加 |
| プッシュ通知・能動的な通知 | チャットはユーザー起点の操作が前提 |
| 音声入力・音声読み上げ | スコープ外。将来のアクセシビリティ改善として検討余地あり |
| 写真→PFC自動入力（AI Vision） | 別機能として次フェーズ候補。本フェーズとは独立して設計する |
